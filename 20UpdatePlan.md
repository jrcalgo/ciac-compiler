# CIaC v0.20 — The Provenance Version: Source Maps for Infrastructure (roadmap forecast)

> Forecast document. Assumes v0.16–v0.19 have landed — provenance
> needs a stable IR/model surface to anchor to, and its highest-value
> consumers are the sim transcripts (v0.17) and system suites whose
> failures it will annotate. Direction-setting; the v0.20 planning
> pass finalizes the provenance-map format and the runtime attribute
> vocabulary. **Confidence label: hypothesis.** Unlike v0.16/v0.19
> (structural) and v0.17/v0.18 (confirmed pillars plus extensions),
> this version bets that closing the runtime→DSL loop changes agent
> and human behavior enough to justify a version. The bet is
> validated cheaply: M1+M2 ship a minimal end-to-end slice first, and
> the plan explicitly narrows if the slice doesn't earn its keep.

## The gap this version closes

Every loop in ciac closes back to the `.ciac` source — except the
outermost one:

1. **Compile-time**: diagnostics point at spans, fixes edit them,
   `explain` narrates them. Closed since v0.1.
2. **Design-time**: hover/completion/rename/semantic-diff all speak
   in constructs. Closed through v0.18.
3. **Test-time, partially**: a failing generated test names a
   Python/Rust file and line *in the generated tree*. The developer
   — or agent — must reverse-engineer which construct generated that
   file. Half-open.
4. **Run-time: fully open.** A 500 in production is a stack trace
   through `app/routers/orders.py` — generated code the author was
   told not to read. A slow trace in Jaeger is a span named after an
   HTTP route. A worker crash-loop is a log line in a container. In
   every case the *fix* is an edit to a `.ciac` construct or a seeded
   handler, and *nothing* in the system says which one. Today that
   mapping lives only in the reader's head — for an agent, it's pure
   inference over generated code it must first ingest.

The compiler is the only component that ever knew the mapping — it
*had* every span in `NormalizedIr` (`Node.span`, `Step.span`,
declaration spans throughout) and dropped them at the codegen
boundary, because `model.rs`'s `Ctx` carries names but not origins.
Provenance is not new information; it is information ciac already
computes and currently throws away.

**v0.20 theme: every artifact, log line, span, and failure knows
which line of `.ciac` it came from — the whole
spec → build → run → fail → fix loop stays inside the DSL.**

## Pillar 1 — The provenance map

- **Span threading**: `model.rs`'s per-construct contexts (`ApiCtx`,
  `WorkerCtx`, `JobCtx`, `ChannelCtx`, `ResourceCtx`, `RecordCtx`,
  handler refs, pipeline steps) gain an `origin: OriginCtx { file,
  line, column, construct_id }` resolved through the same
  `SourceFile::line_col` pipeline the `--json` envelope uses.
  `construct_id` is a stable, human-readable key
  (`api:Checkout.Submit`, `worker:Ship`, `crud:Order.update`,
  `step:Submit.publish[Placed]`) — stable across regeneration for
  unchanged constructs, which is what makes it usable as a log/span
  attribute.
- **The artifact**: every build emits `provenance.json` at the
  output root (system root for multi-service) — schema-versioned like
  the snapshot (v0.18) and the protocol schema (v0.10):
  - `constructs`: construct_id → source location + the generated
    files/regions it owns;
  - `files`: generated path → contributing construct_ids;
  - `routes`: method+path → construct_id (the runtime join key);
  - `subjects`: broker subject → producer/consumer construct_ids.
- **Determinism preserved by design**: provenance lives in the
  sidecar file, *not* as per-line comments sprayed through generated
  code — inline annotations would churn every golden snapshot and
  every regeneration diff for zero runtime value. Generated files
  keep only their existing one-line "Generated by CIaC" headers, now
  with the construct_id appended.

## Pillar 2 — Runtime correlation

The generated apps stamp the construct vocabulary into everything
they emit:

- **Spans** (when `tracing OpenTelemetry` is declared): every
  route/worker/job span gains `ciac.construct` and `ciac.source`
  (`commerce.ciac:42`) attributes — set at the same generated
  instrumentation points v0.15 M3/M4 built, so this is attribute
  plumbing, not new instrumentation.
- **Logs**: the structured-logging setup (`logging Structured`)
  binds `ciac.construct` into the per-request/per-message context, so
  every log line a handler emits carries its origin without the
  author doing anything.
- **Errors**: the generated 500 handler and the worker
  failed-after-retries path log the construct_id alongside the
  exception — the log line an operator actually greps now contains
  the string to feed back into the tooling below.
- No `tracing`/`logging` capability declared → no runtime stamping
  (capabilities stay opt-in); the provenance *map* is emitted
  regardless, since test-time consumers (Pillar 4) don't need the
  runtime half.

## Pillar 3 — `ciac trace` and `ciac locate`

The query side — turning correlation into answers:

- **`ciac locate <generated-path>[:line]`** — offline reverse
  lookup through `provenance.json`: "this file/region was generated
  by `crud:Order` at `commerce.ciac:31`". Also accepts a
  construct_id. The primitive for "I'm staring at generated code,
  take me home."
- **`ciac trace <trace-id> --out <dir>`** — queries Jaeger's API
  (the same endpoint the v0.15 trace-continuity tests already hit),
  joins spans on `ciac.construct`, and renders an ariadne-style
  report *against the `.ciac` source*: the request's path through
  declared constructs, per-hop latency, and the failing hop's span
  events pointed at the construct's source line. A distributed trace,
  rendered as a compiler diagnostic.
- **MCP tools `locate` and `trace`** — same envelopes. For an agent,
  `trace` is the missing observation primitive: production symptom
  in, DSL coordinates out, then the existing loop (edit → fix →
  verify_sim → diff_semantic) takes over. Every step in agent
  vocabulary.

## Pillar 4 — Failure mapping in the test loops

The half-open loop from item 3, closed:

- **Sim transcripts (v0.17)**: every transcript event already names
  a step; events gain construct_ids, and a sim failure report renders
  the failing step's source span — "seed 42, step 17, at
  `commerce.ciac:58` (`step:Submit.call[Billing.Charge]`)". A
  reproducible seed *plus* a source location is a complete,
  self-serve bug report.
- **Generated system suites** (`system_tests.rs`): the generators
  hold IR spans at build time; generated test names/failure messages
  gain the origin ("trace-continuity for `api:Checkout.Submit`
  (traced-checkout.ciac:24) failed: …").
- **LSP**: publish-diagnostics integration for *test* results is cut
  (see cut lines); what ships is hover showing a construct's
  generated-artifact list (from the map) — a small, honest slice of
  "what did this line become".

## Secondary items

- `--json`: `check`/`build` envelopes gain optional construct_ids on
  diagnostics where the span resolves to a known construct (additive,
  JSON_VERSION bump).
- `docs/provenance.md`: the map format, the attribute vocabulary,
  the stability rules for construct_ids (what regenerations preserve
  them, what breaks them — a rename via v0.18's verb preserves;
  delete+recreate doesn't).
- `AGENTS.md` (generated) gains the runtime-symptom playbook:
  symptom → `trace`/`locate` → construct → edit → `verify_sim`.

## Milestones

1. **M1 — span threading + the map**: `OriginCtx` through
   `model.rs`, `provenance.json` emission, schema + staleness test,
   determinism proof (map identical across repeated builds; goldens
   untouched except headers). **This is deliberately the smallest
   end-to-end slice with `locate`** — shippable value before any
   runtime work.
2. **M2 — runtime attributes**: span/log/error stamping, both
   backends, golden-covered; live proof: boot `traced-checkout`,
   curl a request, assert the Jaeger span carries `ciac.source`
   (compose-backed, CI-delegated where the environment lacks Docker,
   per the standing disclosure discipline).
3. **Hypothesis gate**: after M1+M2, the arc pauses for an honest
   usefulness check against real usage (does `locate` get used? do
   stamped spans change debugging time?). A weak signal narrows M3–M5
   to `locate`+test-mapping only and returns the budget; this gate is
   the difference between a hypothesis version and a conviction one.
4. **M3 — `ciac trace` + `locate` CLI/MCP**: Jaeger join, ariadne
   rendering, MCP tools, envelope wiring.
5. **M4 — failure mapping**: sim transcript origins, system-suite
   failure origins, LSP hover artifact-list.
6. **M5 — docs, hardening, 0.20.0**: `docs/provenance.md`,
   AGENTS.md playbook, README, full verification, version bump, arc
   notes.

## Risks

- **The hypothesis is wrong** — provenance is nice but doesn't move
  completion time. Mitigation: the M2 gate above, structurally in the
  plan, with a named narrow-down path.
- **construct_id instability** across refactors silently orphans
  dashboards/log queries. Mitigation: stability rules documented and
  tested; v0.18's rename identity preserves ids; the semantic diff
  reports id changes as `internal` changelist entries so they're at
  least visible.
- **Golden/regeneration churn** from annotation. Mitigation: the
  sidecar-map decision (Pillar 1) is exactly this mitigation; the
  only in-file change is one header line per file, landed as one
  reviewable golden sweep.
- **Jaeger API coupling** (`trace` speaks to one backend's query
  API). Mitigation: already-accepted coupling — the v0.15
  trace-continuity tests pinned it; the join logic is
  collector-agnostic (attributes are OTel-standard), only the query
  client is Jaeger-shaped, and it's isolated behind one module.
- **Attribute cardinality cost** in real observability stacks
  (per-construct attributes are bounded by program size, not
  traffic — low risk, documented anyway).

## Cut lines

- Live LSP integration of runtime state ("this route, p95, last
  error, in the editor"): seductive, unbounded, out. Hover shows
  static provenance only.
- Log-aggregator integrations (Loki/Datadog/CloudWatch query
  clients): the *attributes* are there for any stack; only the
  Jaeger `trace` join ships as a client.
- Provenance for `--deploy` artifacts (k8s manifest lines → DSL):
  the maps include the files; a `kubectl`-aware query tool does not
  ship.
- Historical provenance (mapping *old* deployed builds): the map
  describes the build that emitted it; version it with your
  artifacts.

## After v0.20

Every loop — compile, design, test, run — now terminates in the
`.ciac` source. What ciac has *not* done since v0.13's decision
gates is spend a breadth token: every version since has deepened the
existing surface. v0.21 re-asks the deferred reach questions
(brownfield adoption, the end-user-facing surface, the TypeScript
backend) — this time against five versions of accumulated usage
evidence instead of forecasts, exactly as the v0.12 and v0.15 plans
demanded.
